# Qt 게임 프로토타입 2종 — 비교용

같은 조건(Qt6 + CMake, 핵심 기믹만)으로 두 아이디어를 따로 만들어 놨습니다.
둘 다 돌려보고 **어느 쪽이 더 재밌는지**만 판단하시면 됩니다.

| | 1_WindowPuzzle | 2_TimeEcho |
|---|---|---|
| 조작 | 마우스로 **창을 옮기고 늘인다** | 방향키 + 점프 (평범) |
| 첫인상 | 강함. 처음 보면 놀란다 | 보통. 2~3분 해봐야 온다 |
| "왜 Qt냐"에 대한 답 | 완벽함 (네이티브 창이 곧 게임) | 약함 (다른 걸로도 가능) |
| 기술적 배울 거리 | 전역 좌표계 렌더링, 창 이벤트 | **결정론적 시뮬레이션**(정수 물리, 입력 기록/재생) |
| 확장성 | 레벨 = 창 배치라 설계가 까다로움 | 레벨을 계속 찍어낼 수 있음 |
| 잔버그 위험 | 높음 (창 좌표·포커스·DPI) | 낮음 |

## 빌드 방법 (둘 다 동일)

Qt Creator에서 **File → Open File or Project** → 각 폴더의 `CMakeLists.txt` 선택 → 빌드·실행.

> Qt 6.4 / GCC 환경에서 경고 없이 빌드되는 것까지 확인했습니다.

## 1_WindowPuzzle — 창 자체가 레벨

창 3개가 뜹니다. 캐릭터는 창 안쪽 공간만 돌아다닐 수 있고,
**열려 있는 모든 창의 내부 영역을 합친 것**이 곧 갈 수 있는 공간입니다.

- 1번 창과 2번 창 사이에 틈이 있어 건널 수 없습니다 → **2번 창을 마우스로 끌어다 붙이면 다리가 생깁니다.**
- 창을 겹치면 겹친 부분이 통로가 됩니다.
- 창을 세로로 늘이면 그만큼 위로 갈 수 있습니다.
- 발밑의 창을 확 옮겨버리면 캐릭터가 허공으로 떨어집니다(빨갛게 변함). 아래에 다른 창이 있으면 그 안으로 떨어집니다.
- 목표: 3번 창 쪽에 있는 노란 원까지 가기.

조작 — `←/→` 이동, `Space` 점프, `R` 리스폰, `N` 마우스 위치에 새 창 생성

**꼭 해볼 것**: 캐릭터가 걷는 중에 그 창을 마우스로 끌어보세요. 이게 이 게임의 전부입니다.

## 2_TimeEcho — 과거의 나와 협동

`R`을 누르면 지금까지의 내 움직임이 **유령으로 저장**되고 스테이지가 처음부터 다시 시작됩니다.
다시 시작하면 과거의 내가 그때 그대로 다시 움직이고, 나는 그 옆에서 새로 움직입니다.

**정답 (3회차에 풀립니다)**

1. **1회차** — 왼쪽 끝으로 걸어가 빨간 버튼을 밟고 그대로 서 있기. 문이 열립니다. → `R`
2. **2회차** — 유령1이 버튼을 밟아 문을 열어줍니다. 나는 오른쪽으로 걸어가 **선반 바로 왼쪽**에 가만히 서 있기. → `R`
3. **3회차** — 유령1은 버튼, 유령2는 선반 옆에 서 있습니다. 나는 **유령2의 머리 위로 점프**해 올라간 뒤, 거기서 한 번 더 점프해 선반 위 노란 원에 닿습니다.

조작 — `←/→` 이동, `Space` 점프, `R` 다시(유령 남김), `Backspace` 전부 초기화

---

## 두 개를 섞는 경우

`TimeEcho`의 기록/재생 구조는 "창 위치"까지 그대로 기록할 수 있습니다.
즉 **과거의 내가 창을 옮기던 것까지 재생되는** 게임이 가능하고, 그게 1+2 결합안입니다.
다만 그건 두 프로토타입 중 하나를 먼저 고른 다음에 붙이는 게 순서상 맞습니다.
